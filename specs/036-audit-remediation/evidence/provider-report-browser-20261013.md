# Provider report browser — local implementation evidence

Started 2026-10-12; completed verification 2026-10-13 (Africa/Cairo). Authorized scope: the approved admin report tab, exact selected account, existing HTTP/Worker integration, English/Arabic/Bengali and local synthetic tests. No subagents, live beIN calls, purchase, subscription, payment, business database mutation or deployment.

## Saved behavior and connected boundaries

- `BeinProviderReportPanel` is lazy-loaded through the existing Reports Center registry at `?tab=bein-provider`. Account search shows username/label and configured eligibility. Selection fetches automatically; Refresh applies a changed date range. Default dates cover today and six preceding Cairo calendar days; the inclusive maximum is 31 days, including earlier months. Invoice-descending results have card/invoice search and 50-row paging.
- `useProviderReport` aborts obsolete browser work and fences stale results on account changes. Two-second polling and table pagination read the cached request; they do not enqueue another provider read. Provider package/offer/serial/amount values remain unchanged. Contract dates are explicitly not sale timestamps. Existing table styling and horizontal scrolling, RTL, labels/focus states and localized report-center chrome are reused without a new UI dependency.
- Every new endpoint and the minimal account-options branch requires ADMIN. The options query selects only id/username/label/eligibility flags; credentials, proxies, session data and raw HTML never enter the response. Start validates exact account/date criteria and returns a request ID. Status returns sanitized state/rows and stable error codes. Request/result responses are not shared-cacheable.
- Redis Lua admission allows one active read per account and a 30-second pace. Same-account/same-criteria repeats share an ID; changed criteria during a pending read return busy. A token claims execution once and fences completion; duplicate or interrupted RUNNING jobs never start a replacement scan. Initial request metadata survives ten minutes so the five-minute wait deadline remains readable; completed/failed results live five minutes. No database table or schema change.
- `READ_PROVIDER_REPORT` enters the existing panel queue with priority 10 and one attempt, preserving the queue limiter. The Worker handles it before operation dispatch. It resolves only the selected account and its existing route/session, checks active/exclusive eligibility, causal reservations and execution leases, owns/renews the existing account lock and checks ownership before HTTP and on a ten-second heartbeat. Busy, disabled or lost ownership never selects another account or force-unlocks someone else's lock.
- A dedicated HTTP client allows only the configured report/login GET/POST requests, binds cancellation, disables automatic transport retries and blocks foreign/mutation redirects. Expiry allows one login attempt and a new scan; CAPTCHA is explicit and does not invoke a solver. Active read budget is at most 60 seconds within the five-minute total deadline. Cancellation reaches an in-flight transport. Display results contain no operation/proof mutation methods.
- `sold-packages-report.ts` accepts optional dates, derives actual WebForms field names/All option value from the current response, preserves Dealer selection, checks echoed criteria through every page and retains completeness/total/watermark checks. Missing/ambiguous controls, changed criteria/dealer/data, page cap or a missing grid produce failure, not empty success. Existing financial callers retain default criteria and existing proof semantics.

## Separate semantic and visual review

The report is an account-scoped provider sales view, including external sales. It is neither an operation-attempt history nor financial completion proof. A visible invoice cannot complete a renewal, change its review decision or alter money. Missing/expired/partial observations are never represented as an authoritative empty report.

Source review traces the tab → hook → ADMIN route → Redis admission → exact-account Worker → read-only HTTP scope → complete scan → Redis page. Financial dispatch, database writes, balance changes and payment entry points are absent from this branch. Default financial scans remain covered by the existing regression suite. Route/session construction is shared with account-bound clients; ownership is checked again before actual provider access.

Screenshots of Arabic at 360px and English at 1280px were visually inspected for populated and empty tables. Filters stack without viewport overflow, labels and error text are legible, mixed provider strings are isolated, and the wide table scrolls within its existing container. All three locales were also exercised by the browser scenarios. This is direct local visual judgment, not user acceptance or proof of the full authenticated server page. Browser artifacts/results are under ignored `output/playwright/bein-provider-report/`.
