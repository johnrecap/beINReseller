No disposable PostgreSQL/Redis service was available for the planned migration and native concurrency runs. Synthetic tests do not establish live beIN response compatibility.

Known attribution limit approved by the maintainer: Sold Report provides no independent sale timestamp. Another identical invoice from the same card/account/package/price on the same Cairo day could be mistaken for this attempt if not already claimed. A crash after saving the Pay-intent marker but before the HTTP request is another instance of that risk. Production acceptance therefore still requires a uniform web/Worker/maintenance cutover, migration test on a disposable database, queue/lease races, live read-only report checks, and separately authorized provider checkout evidence. Never replay Pay or auto-refund solely because Reports is delayed.
